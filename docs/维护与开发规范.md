# 维护与开发规范

- 项目边界见 docs.md；使用说明与部署说明分别维护操作和构建步骤，避免重复大段实现描述。
- 功能保持聚焦于网络启动与文件传输。删除功能时同步移除页面、API、模型、测试和文档，不保留兼容空壳。
- 新数据库使用当前结构，不维护未部署版本的升级迁移。
- 启动文件由服务配置唯一决定；不要根据下载目录中的文件隐式改变选择。
- 修改协议逻辑时添加相关边界测试与必要日志，不在开发机真实网段启动完整 DHCP 做自动化测试。
- 配置改动同步默认值、校验、前端类型、表单和文档。API 错误使用中文，列表返回 []。租约与静态绑定必须事务校验，不能把客户端观测信息作为静态绑定。
- 文件访问复用 filetree 路径映射，通过 os.Root 执行 IO，必须受实际文件系统根目录限制，文本编辑保留白名单与大小上限。
- 启动 URL、WOL 地址、Windows 命令输出分别复用 booturl、netutil、command 模块。
- 前端使用 shadcn-vue（Reka UI）组件和统一主题变量；保持现有业务布局，导航统一四字。组件按需引入，删除不用的生成文件，不恢复旧控件类和手写弹窗。列表使用前进行 Array.isArray 兜底。
- 运行概览与日志共用 eventLog.ts；只在页面打开时连接 SSE，离开即释放；按帧批量更新，缓存上限 1000 条。页面按路由加载，避免全局轮询、外部字体和重复图标依赖。
- 修改 embed.ipxe 必须同步使用说明，并验证三种固件构建产物。固件流水线保留 HTTPS 支持。
- 不提交运行数据、数据库、日志、node_modules、dist、exe。

## 代码质量检查

提交前必须完成以下检查；任何一项失败都应先修复原因，再重跑相关检查。不得通过关闭规则、排除业务目录或添加无依据的忽略标记来绕过问题。删除死代码，测试准备与关键操作必须检查错误；允许忽略的清理错误应说明原因，不应覆盖原始业务错误。

使用已安装的 golangci-lint 和 staticcheck，无需每次安装。首次配置环境或工具与 Go 版本不兼容时，再单独处理工具安装或升级。依赖首次安装或 package-lock.json 变更时运行 `npm ci --prefix web`。

在仓库根目录依次执行（前端产物会嵌入 Go 程序）：

```sh
# Vue / TypeScript 严格类型检查及生产构建；build 已包含 typecheck
npm run build --prefix web

# Go 静态检查与测试
golangci-lint run --timeout=5m
staticcheck ./...
go vet ./...
go test ./...
```

前端目前没有独立 ESLint 检查；不把类型检查命名为 lint。涉及页面、交互或接口变更时，还须构建最新程序后运行真实浏览器测试，避免使用旧 exe：

```sh
# Windows；其他平台输出为 dist/pxe
go build -trimpath -ldflags="-s -w" -o dist/pxe.exe ./cmd/pxe
npm run test:e2e --prefix web
```

界面测试使用隔离数据目录；Windows 默认使用已安装的 Edge，其他平台需准备 Playwright 浏览器。检查失败时查看 `tmp/ui-test-results` 的截图和 trace。涉及并发修改时，在具备支持 CGO 的 C 编译器的环境中补充 `go test -race ./...`。

通过标准：上述适用命令全部成功，静态检查无报告；Go 文件符合 gofmt，`git diff --check` 无空白错误。工具不可运行或环境缺少依赖时，必须记录未验证项，不得声称全部通过。

生产构建使用 go build -trimpath -ldflags="-s -w"。发布由 GitHub Actions 手动触发，应用、镜像和固件是独立发布链路。
