# 维护与开发规范

- 项目边界见 docs.md；使用说明与部署说明分别维护操作和构建步骤，避免重复大段实现描述。
- 功能保持聚焦于网络启动与文件传输。删除功能时同步移除页面、API、模型、测试和文档，不保留兼容空壳。
- 新数据库使用当前结构，不维护未部署版本的升级迁移。
- 启动文件由服务配置唯一决定；不要根据下载目录中的文件隐式改变选择。
- 修改协议逻辑时添加相关边界测试与必要日志，不在开发机真实网段启动完整 DHCP 做自动化测试。
- 配置改动同步默认值、校验、前端类型、表单和文档。API 错误使用中文，列表返回 []。租约与静态绑定必须事务校验，不能把客户端观测信息作为静态绑定。
- 文件访问复用 filetree 路径映射，通过 os.Root 执行 IO，必须受实际文件系统根目录限制，文本编辑保留白名单与大小上限。
- 启动 URL、WOL 地址、Windows 命令输出分别复用 booturl、netutil、command 模块。
- 前端保持现有样式；按钮文字横排，列表使用前进行 Array.isArray 兜底。
- 仪表盘与日志共用 eventLog.ts，避免重复 SSE 连接和无上限日志堆积。
- 修改 embed.ipxe 必须同步使用说明，并验证三种固件构建产物。固件流水线保留 HTTPS 支持。
- 不提交运行数据、数据库、日志、node_modules、dist、exe。

提交前运行（顺序不可颠倒，Go embed 需要前端产物）：

```sh
npm ci --prefix web
npm run typecheck --prefix web
npm run build --prefix web
go test ./...
go vet ./...
# 安装了支持 CGO 的 C 编译器时运行：go test -race ./...
```

生产构建使用 go build -trimpath -ldflags="-s -w"。发布由 GitHub Actions 手动触发，应用、镜像和固件是独立发布链路。
