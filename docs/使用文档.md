# 使用文档

## 首次启动

1. 运行 pxe，访问管理面板，创建至少 8 位密码的管理员账号。
2. 在服务配置填写客户端可达的通告 IPv4。已有路由器分配地址时使用默认 ProxyDHCP；完整 DHCP 仅用于明确规划的网络。
3. 在文件管理的 TFTP 目录上传对应架构固件，或到“固件下载”页面下载固件。
4. 在服务配置的启动文件中指定文件，保存配置。在运行概览启动服务，确认状态和日志正常；监听失败会显示错误并停止此次已启动的模块。
5. 在客户端选择网络启动。

配置保存后需停止再启动服务。程序启动只打开管理 Web，不自动启动 DHCP、TFTP 等网络服务。

## 页面导航

| 页面 | 用途 |
|---|---|
| 运行概览 | 查看状态、启动或停止服务 |
| 服务配置 | 设置网络和启动文件 |
| 设备管理 | 管理地址绑定、远程唤醒 |
| 文件管理 | 上传镜像、编辑启动脚本 |
| 固件下载 | 下载 netboot.xyz 固件 |
| 账号管理 | 添加或删除登录账号 |
| 运行日志 | 查看实时运行记录 |
| 系统诊断 | 检查权限、网卡和 DHCP 冲突 |

顶部“刷新”更新当前页面。修改配置或编辑文件后，离开页面前会提示保存；确认放弃后不会保存修改。

## 启动文件与启动链路

客户端先通过 DHCP/ProxyDHCP 获取按架构配置的固件路径，再通过 TFTP 下载。所有固件选择以启动文件配置为准，下载文件不会改变选择。

| 架构 | 自定义固件示例 | netboot.xyz 固件示例 |
|---|---|---|
| BIOS | undionly.kpxe | netboot/netboot.xyz.kpxe |
| UEFI x64 | ipxe-x86_64.efi | netboot/netboot.xyz.efi |
| UEFI ARM64 | ipxe-arm64.efi | netboot/netboot.xyz-arm64.efi |
| UEFI IA32 / ARM32 | 填写自行提供的对应文件 | 不提供默认文件 |

相对路径从 TFTP 根目录读取；netboot/ 前缀映射到下载目录。未提供固件的架构应留空，不跨架构回退。

- 自定义固件使用编译时嵌入的 embed.ipxe。该脚本提供 Debian 13、Alpine、netboot.xyz、诊断、Shell 和本地启动入口；修改后必须重新编译并替换固件。
- 下载的 netboot.xyz 固件使用上游自身的启动逻辑。本程序只负责下载和传送固件，不生成额外钩子。
- 通用 iPXE 再向 DHCP 请求启动目标时，服务返回 HTTP Boot 的 /boot.ipxe，不再次下发固件。请在 HTTP 根目录自行创建 boot.ipxe；HTTP Boot 关闭时不提供后续启动目标。

例如 HTTP 目录中的 boot.ipxe 可以包含：

```ipxe
#!ipxe
chain https://boot.netboot.xyz || shell
```

本地 Linux 脚本示例（先准备匹配架构的文件）：

```ipxe
#!ipxe
kernel http://192.168.1.10/linux initrd=initrd.gz ip=dhcp
initrd http://192.168.1.10/initrd.gz
boot
```

服务不自动下载发行版的内核、initrd、ISO 或软件包仓库。离线安装还需要完整离线软件源，仅将引导文件放在本地不等于离线安装。

## 文件与 netboot.xyz

- TFTP：data/boot/tftp，存放第一阶段固件。
- HTTP Boot：data/boot/http，存放 boot.ipxe、内核、initrd、镜像等。
- netboot.xyz：data/boot/netboot，下载固件可通过 TFTP/HTTP 的 netboot/ 前缀访问。
- 文件管理支持上传、新建目录、小型文本编辑、重命名和删除。文本编辑最多 1 MiB；单文件 Web 上传默认最多 32 GiB。上传不会覆盖同名文件；已存在文本通过在线编辑修改。
- 下载前显示来源，页面展示目标目录及文件校验值。已有非空文件不会重复下载。固件下载最大 64 MiB，完整下载后才写入最终文件，不会隐式切换到其他下载源。
- Web 上传直接流式写入目标磁盘，内存占用不随镜像大小增长；页面显示进度并支持取消。100% 表示浏览器发送完毕，服务器保存成功后才提示完成。最多同时上传两个文件，单次最长 6 小时；暂不支持断点续传，中断后需重新上传。
- 在 `pxe.toml` 的 `[admin]` 下设置 `max_upload_bytes = 34359738368` 可调整 Web 上传上限（字节，范围 1 字节至 1 TiB），重启程序生效；页面自动显示实际值。此限制独立于 TFTP 上传和 netboot.xyz 固件下载的 64 MiB 上限，ISO 应通过文件管理上传到 HTTP 目录。
- 上传临时文件使用保留前缀 `.pxe-upload-`，文件管理、HTTP 和 TFTP 均禁止访问。完成后通过同目录硬链接发布，避免覆盖同名文件；目标文件系统必须支持硬链接（例如 NTFS、ext4，不支持 FAT/exFAT）。不支持时上传失败并清理临时文件，可直接在服务器本地复制镜像。
- 失败或取消会清理临时文件；程序异常退出遗留的临时文件，在下次向同一目录上传时清理超过 24 小时的文件。需要预留至少一个完整文件的可用空间；磁盘写入失败不会发布不完整的目标文件。不要将上传目录通过其他文件服务暴露给不可信用户。
- TFTP 上传默认关闭，可按需启用，受上传大小和并发限制。

## 客户端、共享与诊断

“设备管理”页面用于维护设备信息、静态地址和 MAC，也支持批量创建和 Wake-on-LAN。静态绑定由管理员填写；最近观测 IP、固件和状态由网络请求更新，不能通过探测改写静态绑定。租约持久保存，重启后继续校验占用和到期时间。ProxyDHCP 不分配地址，静态绑定仅在完整 DHCP 模式下生效。

WOL 需要设备固件/网卡启用网络唤醒，网络允许 UDP 7/9 广播。

Windows 可由程序创建 SMB 共享，需要相应权限；Linux/macOS 手动配置 Samba 或系统共享。

HTTP Boot 的 /client/report 接收 POST 健康报告；管理 API 的 /api/v1/clients/report 需要登录。公开 HTTP 报告只使用连接来源 IP，不接受报告中指定其他设备 IP。客户端健康信息是设备上报，不代表服务器主动检测。

## 登录与日志

会话有效期 24 小时；右上角可退出。修改密码后原会话失效，需要重新登录。删除用户同时撤销其会话。

日志位于 data/logs/pxe.log，达到 10 MiB 后轮转到 pxe.log.1，仅保留一份备份。数据库事件保留最近 5000 条。

## 故障排查

- 管理页面可访问但不能 PXE：检查运行概览是否已启动服务，以及 UDP 67/69/4011、HTTP Boot 端口和防火墙。
- 找不到固件：核对文件是否在正确目录，路径和架构是否匹配；netboot.xyz 文件需填写 netboot/ 前缀。
- 通用 iPXE 找不到 boot.ipxe：在 HTTP 目录创建该文件，并启用 HTTP Boot。
- 修改配置无效：停止再启动服务；修改 embed.ipxe 后需重新编译固件。
- Linux 一键脚本下载固件到 /opt/netboot，需要复制到默认 TFTP 目录 /opt/netboot/data/boot/tftp 或调整根目录。
